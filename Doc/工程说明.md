# MSPM0G3519 工程说明

## 1. 项目用途

TraceTrackCar_TI 是小车工程的 MSPM0G3519 版本，保留 Common、Algorithm、APP、Route 和 Test 公共接口，重新实现 BSP、启动配置和芯片相关外设。

功能包括电机与编码器、灰度循迹、姿态估计、测距、称重、LCD/OLED、K210、E220、路线管理和整车任务状态机。

## 2. 分层

| 层级 | 职责 |
| --- | --- |
| `User/Common` | 平台无关状态码和临界区接口 |
| `User/BSP` | MSPM0 外设、引脚、中断、环形缓冲区和时基 |
| `User/Driver` | 器件驱动 |
| `User/Algorithm` | PID、循迹、里程和姿态等纯算法 |
| `User/APP` | 底盘、动作、传感器管理、显示和状态机 |
| `User/Route` | 赛道规则和路线输出 |
| `User/Test` | 专项测试入口 |
| `User/Config` | SysConfig 源文件和生成文件 |

```text
APP / Route / Test
        ↓
Algorithm / Driver
        ↓
BSP
        ↓
MSPM0 DriverLib / SysConfig
```

上层不得直接使用具体 UART、GPIO、IOMUX、DMA 或中断宏。

## 3. 启动流程

```text
BSP_InitAll()
→ Driver_Init()
→ App_Init()
→ Scheduler_Init()
→ Scheduler_Run()
```

`BSP_InitAll()`内部完成 SysConfig 生成初始化和板级初始化。所有周期功能采用非阻塞静态任务表。

## 4. 配置入口

| 文件 | 作用 |
| --- | --- |
| `User/Config/empty_mspm0g3519.syscfg` | 外设实例、引脚、时钟和 DMA |
| `User/BSP/vehicle_config.h` | 2WD/4WD 和 UART4 直连/E220 模式 |
| `User/Algorithm/control_config.h` | 底盘、循迹和动作参数 |
| `User/Driver/drv_gray_sensor.h` | 灰度来源 |
| `User/APP/task_profile_config.h` | 整车状态机选择 |
| `User/Route/route_config.h` | 赛道选择 |
| `User/APP/app_task_config.h` | 静态任务表 |
| `User/Test/test_config.h` | 专项测试开关和 E220 ID |

## 5. SysConfig

```text
修改 empty_mspm0g3519.syscfg
→ 重新生成 ti_msp_dl_config.c/.h
→ 检查 Git 差异
→ Rebuild
```

不要只手工修改生成文件。

## 6. 构建

- Keil：`keil/TraceTrackCar_TI.uvprojx`
- TI Clang：`ticlang/makefile`
- GCC：`gcc/makefile`
- IAR：`iar/makefile`

新增或移动固件 `.c` 文件时同步更新实际使用的构建入口。当前上板以 Keil AC6 为主。

## 7. 上层同步

```text
Common
Algorithm
Route
大部分 APP
Test
```

```c

UART_PORT_E220
DEBUG_UART_PORT
```

芯片差异只放在 BSP、Config、启动文件和中断入口。
