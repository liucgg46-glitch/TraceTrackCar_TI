# MSPM0G3519迁移工程测试任务完整手册

> 源码基准：`112f613658c113ba958fc2c5b63a62ea5dfe74f5`。本文以“复制任务表即可测试”为目标，每一项给出完整任务表、操作、输出和通过标准。

## 0. 使用前必须完成

1. 将 `User/Test/test_config.h` 中的 `PROJECT_TEST_TASKS_ENABLE`设为`1U`。
2. 在 `User/APP/app_task_config.h` 中包含 `test.h`。
3. 确认 `User/Test/test.c`参与 Keil Target；K210 专项测试还要加入 `User/Test/test_k210_comm.c`。
4. 每次只复制本文一个完整任务表，不从不同章节抽几行拼接。
5. 测试结束后恢复正式任务表，并将测试开关恢复为`0U`。

### 统一规则

- 除 GPIO 专项外，运行心跳统一使用 `AppDiagnostics_HeartbeatUpdate()`。
- `Test_GPIO_Toggle()`只用于 GPIO 专项，不再充当其他测试的运行指示。
- `AppTask_BSP_Background()`必须保留。
- 按键任务顺序：`Key_Update()`在消费事件的任务之前。
- 传感器任务顺序：`Sensor_Update()`在读取缓存的测试之前。
- 底盘任务顺序：`Encoder_Update()`在 `Chassis_Update()`之前。
- 同时只能有一个任务控制电机或显示页面。

## 1. BSP 普通 GPIO 翻转测试

**对应入口：**`Test_GPIO_Toggle`

### 可直接复制的完整任务表

```c
#define APP_SCHEDULER_TASK_LIST_DEFINE()                         \
Task_t task_list[] = {                                           \
    { AppTask_BSP_Background, 1U, 0U }, /* 后台维护 */                  \
    { Test_GPIO_Toggle, 10U, 0U }, /* 测试 BSP_GPIO_CH1 */            \
};                                                               \
const uint8_t TASK_NUM =                                         \
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

`Test_GPIO_Toggle()`每 500 ms 翻转一次 `PA14 / LED1 / BSP_GPIO_CH1`。本项不要再注册
`AppDiagnostics_HeartbeatUpdate()`，因为两者控制同一个逻辑 GPIO，同时翻转会导致现象混乱。

**通过标准：**对应 LED 或测试引脚稳定以约 1 Hz 的亮灭周期变化。

## 18A. 灰度传感器按键校准

**对应入口：**`LineCalibration_Update`

这是灰度传感器专用校准任务，不属于 `Test_` 前缀测试函数。它的按键定义为：

| 按键 | 校准行为 |
| --- | --- |
| KEY1（PB0 / A08） | 采集当前八路数据作为白色区域样本 |
| KEY2（PB1 / A09） | 采集当前八路数据作为黑色区域样本 |
| KEY3（PB13 / B10） | 根据白色和黑色样本生成八路阈值 |
| KEY4、KEY5 | 本任务不使用 |

### 可直接复制的完整任务表

```c
#define APP_SCHEDULER_TASK_LIST_DEFINE()                         \
Task_t task_list[] = {                                           \
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U }, /* 运行心跳 */         \
    { AppTask_BSP_Background, 1U, 0U }, /* UART、总线和异步驱动后台 */        \
    { Key_Update, 10U, 0U }, /* 按键扫描，必须在校准任务之前 */                 \
    { Sensor_Update, 1U, 0U }, /* 持续更新灰度传感器数据 */                    \
    { LineCalibration_Update, 10U, 0U }, /* KEY1白色、KEY2黑色、KEY3生成阈值 */ \
    { LCD_Update, 20U, 0U }, /* 刷新LCD校准页面 */                       \
    { OLED_Update, 20U, 0U }, /* 刷新OLED校准页面 */                     \
};                                                               \
const uint8_t TASK_NUM =                                         \
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

没有连接 LCD 或 OLED 时，可以删除对应的显示刷新任务；`Key_Update()`、`Sensor_Update()`和
`LineCalibration_Update()`不能删除。

### 校准操作顺序

1. 将八路灰度探头全部放在白色区域，等待数据稳定。
2. 按一下 KEY1，程序保存八路白色样本并显示/输出 `WHITE ...`。
3. 将八路灰度探头全部放在黑色区域，等待数据稳定。
4. 按一下 KEY2，程序保存八路黑色样本并显示/输出 `BLACK ...`。
5. 按一下 KEY3，程序计算八路阈值。
6. 记录输出的八行默认阈值宏，按需要写入 `User/Algorithm/line_detect.h`。

KEY3生成成功后会输出：

```text
GRAY CAL THRESHOLDS READY
#define LINE_DETECT_DEFAULT_THRESHOLD_0 ...
#define LINE_DETECT_DEFAULT_THRESHOLD_1 ...
...
#define LINE_DETECT_DEFAULT_THRESHOLD_7 ...
```

没有先完成 KEY1和KEY2时按 KEY3，会输出：

```text
GRAY CAL WAIT: PRESS KEY1 AND KEY2 FIRST
```

灰度传感器未在线时会输出：

```text
GRAY CAL WHITE FAILED: SENSOR OFFLINE
```

或：

```text
GRAY CAL BLACK FAILED: SENSOR OFFLINE
```

生成一次阈值后，白色和黑色采集完成标志会被清除；再次校准时必须重新按 KEY1、KEY2、KEY3。

### 串口输出位置说明

当前 TI 源码中的 `LineCalibration_Send()`使用 `UART_PORT1`，在本工程中对应
UART4 / E220，而不是 Type-C / CH340 的 UART0 调试口。因此：

- LCD/OLED连接正常时，可以直接通过显示页面观察校准进度；
- 需要在 Type-C 串口查看 `WHITE`、`BLACK`和阈值宏时，应将
  `User/APP/line_calibration.c`中的 `UART_PORT1`改为 `DEBUG_UART_PORT`。

校准期间不要同时注册 `Test_Key_Update()`、蜂鸣器按键测试、底盘按键测试或其他会读取
KEY1～KEY3按下事件的任务，否则按键事件可能被其他任务先消费。
