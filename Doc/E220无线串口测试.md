# E220无线串口双向通信测试

## 1. 硬件连接

MSPM0G3519端使用UART4：

| MSPM0G3519 | E220 |
| --- | --- |
| PB10 / UART4_TX | RXD |
| PB11 / UART4_RX | TXD |
| PB28 | AUX |
| GND | GND |

E220使用115200、8N1。透明传输模式下M0、M1必须可靠接地，两个无线模块的地址、信道、空中速率和UART参数必须能够互通。

## 2. 任务注册

```c
#define APP_SCHEDULER_TASK_LIST_DEFINE()                         \
Task_t task_list[] = {                                           \
    { AppDiagnostics_HeartbeatUpdate, 10U, 0U },                 \
    { AppTask_BSP_Background,     1U, 0U },                      \
    { Test_E220_Link_Update,     10U, 0U },                      \
};                                                               \
const uint8_t TASK_NUM =                                         \
    (uint8_t)(sizeof(task_list) / sizeof(task_list[0]))
```

`AppTask_BSP_Background`必须保留，它推进UART发送、E220延迟队列、LCD SPI和OLED I2C状态机。

E220测试函数直接刷新LCD和OLED，不需要额外注册`LCD_Update`或`OLED_Update`。同时注册其他显示任务会争用同一显示设备。

## 3. 本机ID

测试默认调用`BSP_GetDeviceIdHash()`，由MSPM0 Factory Region的Trace ID生成本机ID，不再读取STM32F407的`0x1FFF7A10`地址。

通常两块板会自动得到不同的`SELF ID`。若两块板LCD上显示相同ID，可分别修改：

```c
#define TEST_E220_SELF_ID_OVERRIDE 0U
```

例如一块板设为`1U`，另一块板设为`2U`。`0U`表示自动生成。

## 4. 显示和调试日志

LCD应在无线模块未连接时也显示：

```text
E220 CAR LINK TEST
SELF ID:xxxx
TX:...
PEER ID:----
RX:----------
LINK:WAIT
```

Type-C调试串口每500 ms输出一次：

```text
E220 self=xxxx aux=1 tx=... rx=... count=... link=WAIT queue=... defer=... retry=...
```

判断方法：

- LCD完全不亮：先检查程序是否持续运行、LCD是否Ready，以及是否误注册了其他LCD任务。
- `aux=0`长期不变：检查AUX接线、模块供电和M0/M1工作模式。
- `tx`递增但对端无接收：检查PB10/PB11交叉接线、波特率、信道和模块参数。
- `uart_rx`有数据但`count`不增加：收到的数据不符合`E220,ID,VALUE`加换行的测试帧格式。
- 两块板`SELF ID`相同：为两块板设置不同的`TEST_E220_SELF_ID_OVERRIDE`。

## 5. 代码边界

芯片唯一标识读取属于BSP。Test层只能调用`BSP_GetDeviceIdHash()`，不得再次直接访问STM32或MSPM0的芯片专用地址。
